# Koki autonomous agent: activation and release gate

This release adds a 15-minute market-evaluation cycle and an on-chain indexer for **realized treasury fee claims**. It does not autonomously deploy new mainnet tokens. The current launch flow requires an explicit wallet signature, and this release keeps that safety boundary intact.

## 1. Apply database migrations

Apply these SQL files to the Supabase project connected to Koki, in order:

1. `supabase/migrations/202610120001_agent_ledger.sql`
2. `supabase/migrations/202610130001_fee_indexer_cursor.sql`

The first creates the agent session, cycle, market observation, and fee ledger tables. The second adds block provenance and the persistent RPC scan cursor.

## 2. Configure Vercel environment

Set these in the Koki Vercel project's encrypted environment settings for Production (and Preview if you want previews to run):

- `NEXT_PUBLIC_SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `CRON_SECRET`

Use a long, random secret generated by a password manager. Do not put its value in source control, logs, chat, or client-side variables. A missing secret now causes protected cron routes to fail closed.

Optional:

- `AGENT_FEE_SCAN_FROM_BLOCK`: set to the earliest block you want to index. If omitted, the first run scans only the most recent 2,000 confirmed blocks, then persists a cursor. Set the deployment block before first activation if you require a historical backfill.

## 3. Configure GitHub Actions scheduler

In GitHub repository Settings → Secrets and variables → Actions:

- Add repository **secret** `CRON_SECRET` with exactly the same value as Vercel.
- Add repository **variable** `KOKI_AGENT_URL` with the deployed base URL, for example `https://koki-blush.vercel.app` (no trailing slash required).

The workflow `.github/workflows/agent-loop.yml` runs every 15 minutes and can also be started manually from the Actions tab. It records a market-evaluation cycle first, then reconciles confirmed fee claims.

## 4. What the fee indexer counts

The authenticated endpoint `POST /api/agent/fees/reconcile` scans confirmed Robinhood Chain logs from the configured launchpad contracts and fee locker. It records:

- Launchpad `ProtocolFeesClaimed` events emitted after successful treasury transfers.
- Fee-locker `ProtocolClaimed` events only when the claimed currency is canonical WETH, which is ETH-denominated for this accounting view.

Each ledger entry includes transaction hash, log index, block number, block timestamp, amount, and source. A database unique key makes replays idempotent. The cursor advances only after ledger writes succeed. Five recent blocks are held back for confirmation.

## 5. Important limits

- **This is not an earnings guarantee.** Volume is not revenue; only confirmed treasury claim events count as realized fees.
- The indexer does not count unclaimed contract balances, unclaimed LP fees, non-WETH token fees, or unrelated wallets' revenue.
- The reported net is revenue minus costs already recorded in the agent ledger. Infrastructure and other off-chain costs must be entered before the figure can be treated as complete accounting profit.
- Existing deployed contracts define their own economics. The repository documents a 1% curve fee with a 75/25 creator/protocol split in the v1 launchpad and a 1% Uniswap V3 pool fee with a 75/25 fee-locker split. This code does **not** silently change those immutable contract terms to 1.5%.
- The market-evaluation loop does not yet automatically launch tokens. The current UI launch path uses wallet signing. Automated mainnet execution needs a separately reviewed execution design, funded gas policy, launch-platform verification, and explicit approval.
- No private keys are stored by this agent, and no mainnet transactions are submitted by the new indexer.

## 6. Verify operation

After deploying the branch and applying the migrations, open `GET /api/agent/health` first. It returns HTTP 200 only when the required environment variables, Robinhood Chain RPC/contract code checks, and both database migrations are present. It never returns secret values. HTTP 503 includes per-check readiness flags to identify what is missing.

Then:

1. Run the workflow manually in GitHub Actions.
2. Confirm the market cycle returns `ok: true`.
3. Call the fee reconciliation endpoint with the bearer secret from a secure operator environment; confirm it returns block range and indexed count.
4. Inspect `agent_fee_ledger` and follow transaction hashes on Robinhood Chain Blockscout.
5. Confirm a repeated run does not duplicate rows and that the cursor advances.
6. Verify any reported revenue against the actual treasury recipient and contract event before treating it as profit.
